## 一、总目标

以 Hutool 5.8.x `hutool-cache` 模块（`cn.hutool.cache.*` 共 **19 个 Java 类**）为蓝本，
实现功能语义完全对齐的 `hutool-cache` crate。**目标 19 个 Java 类 → 19 个独立 Rust 文件**
（禁止合并到 `compat.rs`）。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：`ConcurrentHashMap` → `moka::sync::Cache`；
   `ScheduledExecutorService` → `tokio` 定时器；`ReferenceQueue` → `std::sync::Weak`；
   `CacheListener` → trait 对象；`ReentrantReadWriteLock` → `parking_lot::RwLock` 或 `tokio::sync::RwLock`。
2. **每个 .rs 文件只对应一个 Java 对象**：禁止把多个 Java 类合并到 `compat.rs`。
3. **保留所有已有迁移内容**：hutool-cache 当前已有 27 个 Rust 文件（部分拆分 + 部分 dump），
   顺原思路继续，不得删减已实现代码。
4. **公开类型必须有中文文档注释**：结构体、trait、方法、字段。
5. **依赖 `hutool-core`**：复用 `func/`、`lang/`、`exception/` 等基础设施。
6. **测试覆盖**：每个 cache 实现至少 1 个 FIFO/LFU/LRU/Timed/Weak 的行为测试。

    ScheduledTimedCache, StampedCache, TimedCache, WeakCache,

`lib.rs` 行数应 ≤ 100。

## 四、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| compat.rs 拆分破坏现有 API | 中 | 保留 `pub use` 路径不变；类型从 compat 迁移到独立文件 |
| moka 与 hutool-cache 语义差异 | 低 | FIFOCache 等保留 moka 作为底层；调整 LRU/LFU 策略 |
| `WeakReference` 在 Rust 中的语义差异 | 中 | 用 `Weak<T>` + 定期清理任务 |
| 文件 cache 与 Java File API 差异 | 低 | 用 `std::path::Path` + `tokio::fs` |
