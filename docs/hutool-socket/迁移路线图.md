# hutool-socket 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（`cn.hutool.socket.*`）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Hutool 5.8.x 的 `hutool-socket` 模块（`cn.hutool.socket.*`，20 个非 `package-info`
Java 类）为蓝本，实现功能语义完全对齐的 `hutool-socket` crate。`hutool-socket` 提供
Java NIO/AIO 套接字编程的封装：AIO 客户端/服务器、NIO 客户端/服务器、协议编解码、
ChannelUtil 工具类。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java `java.nio.*` / `java.nio.channels.*` →
   `tokio`；Java `Netty` 风格 → `tokio::sync` + `tokio::io`；Java NIO Selector →
   `tokio::select!`；Java AIO AsynchronousChannelGroup → `tokio::spawn`
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 hutool-rust 一文件一对象规范
3. **公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **保持 Hutool API 形态**：对外暴露 `SocketUtil` / `AioClient` / `AioServer` /
   `NioClient` / `NioServer` / `ChannelUtil` 等命名
6. **完整保留协议抽象（Protocol / MsgDecoder / MsgEncoder）**：用于对接业务层

| 维度 | 当前 | 目标 |

## 六、风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| `compat.rs` 1308 行单源 dump | 严重违反 AGENTS.md 红线 | S1 拆分 20 个文件 |
| AIO Java 异步模型与 Tokio 调度差异 | 语义边界需仔细对照 | 在 `AioSession` 中明确 |
| NIO Selector 单线程 vs Tokio 多线程 | 背压策略需重新设计 | 用 `Semaphore` 限制并发 |
| `Protocol::decode/encode` 同步/异步选择 | Java 同步，Rust 异步 | 提供 `async fn` + sync 包装 |
| `MsgDecoder` 累积缓冲管理 | `bytes::BytesMut` | 文档化 |
| `ChannelHandler` 链式调用 | Rust 用 trait 链 | `ChannelHandler` trait + 闭包 |
| `IoAction` 单方法接口 | Rust `Fn` trait | `fn doAction(...)` |
| `Operation` 操作枚举 | 同步位图掩码 | `bitflags` crate |
| `SocketConfig` Java 反射注入 | Rust builder 模式 | 已实现 `TcpConfig` |
| TCP 半关闭 vs Tokio `shutdown` | API 差异 | 文档化 |
