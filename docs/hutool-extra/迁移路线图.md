# hutool-extra 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（`cn.hutool.extra.*`）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Hutool 5.8.x 的 `hutool-extra` 模块（`cn.hutool.extra.*`，128 个非 `package-info` Java
类）为蓝本，实现功能语义完全对齐的 `hutool-extra` crate。`hutool-extra` 是 Hutool 的
"扩展集"——所有不便归入 `hutool-core` 的能力（模板引擎、邮件、FTP、SSH、二维码、表情、
压缩、Cron、拼音、表达式、脚本、分词、Spring 桥接、Bean 校验）都在此。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象；Spring → axum
   桥接层；Velocity/Freemarker → Tera/Handlebars；JSch → russh；JavaMail → lettre
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 hutool-rust 一文件一对象规范
3. **每个模板引擎引擎一个独立 mod**：velocity → handlebars_rust、freemarker → tera、
   thymeleaf → askama、jsp/twirl → maud
4. **公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
5. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
6. **不实现完整 Spring 容器**：仅提供 `ApplicationContext` trait 抽象，桥接到
   `hutool-vernal::ApplicationContext`

### 与 hutool-extra 当前状态的差距

| 维度 | 当前 | 目标 |
|------|------|------|
| Java 类数 | 128 | 128 |
| Rust 文件数 | 87 | 128+ |
| 子模块数 | 16 | 16 |
| 模板引擎 | 0（仅占位 trait） | 6（tera/handlebars/askama/maud/…） |
| 表达式引擎 | 0（仅 ExpressionEngine trait） | 5（aviator/jexl/rhino/spel/…） |
| 分词引擎 | 0（仅 TokenizerEngine trait） | 8（ansj/hanlp/jieba/word/…） |
| 拼音引擎 | 5（Pinyin4j/Houbb/Bopomofo4j/Tiny/Default） | 5（已对齐） |
| 邮件（SMTP） | ✅ lettre 集成 | ✅ 已对齐 |
| FTP | 占位 FtpMode 枚举 | ftp 客户端（suppaftp/async-ftp） |
| SSH/SFTP | 命名占位 | russh 实现 |
| 二维码 | ✅ qrcode 集成 | ✅ 已对齐 |
| 表情 | ✅ | ✅ 已对齐 |
| 压缩/解压 | ✅ zip（限速/防穿越） | ✅ 主线；7z 后续 |
| Cron | ❌（走 hutool-cron） | ❌ 不在本 crate |
| Spring 桥接 | 抽象 ApplicationContext trait | 已对齐骨架 |

## 五、风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 模板引擎生态碎片化 | S2/S3 工期不可控 | 默认仅交付 Tera+Handlebars 2 个，Askama/Maud 列入备选 |
| Aviator/JEXL Java 字节码执行 | S7 需重写语义 | 改用 `rhai` 脚本引擎统一提供；保留 trait 抽象 |
| 中文分词模型 | S8 中文分词需训练数据 | 优先集成 `jieba-rs`，其他引擎保留 trait 占位 |
| Spring 桥接语义差异 | S9 抽象粒度难定 | 与 `hutool-vernal` 联合设计 trait |
| JSch → russh API 差异较大 | S5 工期最长 | 优先实现 `Connector`/`ChannelType`/`SessionPool`，Sftp 完整命令列表分阶段 |
