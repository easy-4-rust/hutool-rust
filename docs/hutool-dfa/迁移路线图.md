## 一、总目标

以 Hutool 5.8.x `hutool-dfa` 模块（`cn.hutool.dfa.*` 共 **5 个 Java 类**）为蓝本，
实现功能语义完全对齐的 `hutool-dfa` crate。**目标 5 个 Java 类 → 5 个独立 Rust 文件 + Rust 扩展**。

## ✅ 当前状态

`hutool-dfa` 是 **5 个目标模块中唯一完全合规的 crate**：所有 Java 类已拆分到独立
Rust 文件，无 compat.rs dump 违规，结构对齐 100%。

## 二、设计原则

1. **功能语义对齐，实现方式 Rust 化**：
   - `HashMap<Character, Map>` → `HashMap<char, WordTree>` 嵌套
   - `ArrayList<FoundWord>` → `Vec<FoundWord>`
   - `StringBuilder` → `String` + `push_str`
   - `String.charAt(i)` → `s.chars().nth(i)`
   - `StringBuilder.setCharAt` → `String::replace_range`
2. **每个 .rs 文件只对应一个 Java 对象**
3. **公开类型必须有中文文档注释**
4. **依赖 `hutool-core`**：复用 `lang/`, `util/` 等基础设施
5. **测试覆盖**：DFA 构建、敏感词匹配、序列化各 1+ 测试

## 五、API 详解

### `WordTree`（AC 自动机 / 字典树）

```rust
let mut tree = WordTree::new();
tree.add_word("敏感词");
tree.add_word("另一个");

let matches = tree.match_all("这是一段包含敏感词的文本");
// FoundWord { word: "敏感词", start: 7, end: 10 }
```

### `SensitiveUtil`

```rust
let mut tree = WordTree::new();
tree.add_word("badword");

let json = SensitiveUtil::serialize(&tree)?;
let restored = SensitiveUtil::deserialize(&json)?;
```

### `SensitiveProcessor`

```rust
let processor = DefaultSensitiveProcessor::new(word_tree);
let result = processor.process("包含badword的文本", '*');
// -> "包含*******的文本"
```

### `StopChar`

```rust
StopChar::is_stop_char(' ');  // true（默认停用字符）
StopChar::is_stop_char('中');  // false
StopChar::DEFAULT_STOP_CHARS; // 常用停用字符集合
```

## 六、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| AC 自动机实现复杂度 | 中 | 用 HashMap 嵌套实现简单 AC |
| 字符迭代效率（中文） | 低 | `chars()` 迭代器 |
| 序列化兼容性 | 低 | 用 JSON 通用格式 |
| 停用字符 Unicode 覆盖 | 中 | 默认 + 扩展接口 |
