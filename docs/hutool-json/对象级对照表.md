## 命名与组织规则

1. 目录、文件名一律 snake_case；类型 PascalCase；方法 snake_case
2. **每个 `.rs` 文件只对应一个 Java 对象**（除 crate 门面 / 集成层）
3. `mod.rs` 只做模块声明与 re-export，**禁止定义任何类型/逻辑**
4. Java 多层嵌套包只要求**最后一层目录**完全对齐
5. 每个文件头部必须有中文 doc 注释：说明对应 Java 类的全限定名、核心职责
6. 方法级中文注释从 Java 源码同步翻译

## 4. compat.rs 拆分计划（🔴 优先）

将 `compat.rs`（1020 行）拆为以下 6 个独立文件：

| 新 Rust 文件 | Java 类 | 行数（估算） | 内容 |
|---|---|---|---|
| `compat/json_config.rs` | `JSONConfig` | 200 | 9 个 bool 开关 + date_format |
| `compat/json_object.rs` | `JSONObject` | 350 | `Map<String, Value>` newtype + Deref |
| `compat/json_array.rs` | `JSONArray` | 200 | `Vec<Value>` newtype + Deref |
| `compat/json_null.rs` | `JSONNull` | 80 | 单例 + Display |
| `compat/json_container.rs` | `JsonContainer` | 50 | trait 定义 |
| `compat/path.rs` | `get_by_path` + `put_by_path` + `PathError` | 140 | JSONPath 核心 |
| **合计** | — | **1020** | 与原文件大小一致 |

**验收**：
- `compat.rs` 文件大小 < 100 行（仅 re-export）
- 每个新文件 50-350 行
- `cargo build` 通过
- `cargo test` 全部通过
- 公共 API 行为不变
- `pub use` 接口不变
