> 版本：v1.0（2026-07-27）｜基线：hutool **5.8.43+**（hutool-system）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护

## 一、总目标

以 hutool-system 为蓝本实现功能语义对齐的 hutool-system Rust crate：覆盖 Java
端 `SystemUtil` 静态工具 + 8 个 POJO（OsInfo / HostInfo / JvmInfo / JavaSpecInfo
/ JavaRuntimeInfo / UserInfo / JvmSpecInfo / ManagementInfo / RuntimeInfo /
CompilationInfo）以及 `oshi` 子包（OshiUtil + 7 个硬件信息 POJO）。

底层使用 **`sysinfo`** crate 作为系统快照来源，对应 Java 端的 **OSHI 库**。
由于 Java 与 Rust 平台抽象差异较大，迁移策略：
**只迁移通用字段 + 跨平台保证**；**Linux 特有字段**（如 `/proc/net/route`）
不强制迁移。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java `System.getProperty` 反射 →
   `env::var` / `System::host_name()`；Java 反射 `Runtime` → `sysinfo` / `os_info`
2. **每个 .rs 文件只对应一个 Java 对象**：核心抽象拆为独立模块
3. **公开 API 必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **跨平台兼容**：所有公共 API 在 macOS / Linux / Windows 上行为一致
5. **`unsafe_code` 全 crate 禁止**：`#![forbid(unsafe_code)]`
6. **字段语义化**：Java 端 `getName()` / `getVersion()` → Rust 端字段命名
   `name` / `version`（公开字段）
7. **OSHI 子模块独立**：保留 `oshi/*` 子目录命名（与 Hutool Java 包名对齐）

## 四、与 Java hutool-system 的主要差异

| 维度 | Java 实现 | Rust 实现 | 原因 |
|------|----------|----------|------|
| 平台依赖 | OSHI 跨平台 | sysinfo 跨平台 | 对齐 |
| 系统属性 | `System.getProperty(name)` | `env::var` / `sysinfo::System` | 跨平台 |
| 用户主目录 | `System.getProperty("user.home")` | `env::var("HOME")` / `env::var("USERPROFILE")` | 跨平台 |
| 临时目录 | `System.getProperty("java.io.tmpdir")` | `env::var("TMPDIR")` / `env::temp_dir()` | 跨平台 |
| 内存 | `Runtime.getRuntime().totalMemory()` | `sysinfo::System::total_memory()` | 内置 |
| CPU 核数 | `Runtime.getRuntime().availableProcessors()` | `sysinfo::System::cpus().len()` | 内置 |
| 主机名 | `InetAddress.getLocalHost().getHostName()` | `sysinfo::System::host_name()` | 内置 |
| Java 探测 | `System.getProperty("java.version")` | `env::var("JAVA_VERSION")` + `which java` | 间接 |
| Windows 版本 | `OSVERSIONINFOEX` | `sysinfo::System::os_version()` | 内置 |
| Windows 2000/XP/7 单独 | `OsInfo.isWindows2000()` 等 | 合并到 `is_windows()`，具体版本通过 `version` 字符串判断 | 简化 |
| 文件分隔符 | `System.getProperty("file.separator")` | 平台常量 `cfg!(windows)` 编译期决定 | 类型安全 |
| 用户名 | `System.getProperty("user.name")` | `env::var("USER")` / `env::var("USERNAME")` | 跨平台 |
| 网络接口 | OSHI `NetworkIF` | sysinfo `Networks` | 对齐 |
| 进程列表 | `OperatingSystem.getProcesses()` | sysinfo `System::processes()` | 对齐 |
| OSHI 平台 | 支持 macOS/Linux/Windows | sysinfo 同样支持 | 对齐 |
| `serialVersionUID` | Java 序列化 | 不需要 | 不适用 |
| `Serializable` 实现 | Java Serializable | 不需要 | 不适用 |
| `clone/copy` 语义 | Java `Cloneable` | Rust 派生 `Clone` | 类型安全 |
| `toString()` | Java Object.toString | Rust 显式 `to_string` / `impl Display` | 类型安全 |

## 五、风险与限制

1. **sysinfo 字段**：部分字段在 Windows / macOS / Linux 上行为不一致，
   使用前需在目标平台验证
2. **Java 探测**：依赖环境变量 `JAVA_HOME` / `JAVA_VERSION`，容器化部署时
   可能为空
3. **磁盘路径**：`Disks::new_with_refreshed_list()` 在不同平台返回的字段不同
4. **网络接口**：容器内可能返回虚拟接口，需要业务侧过滤
5. **单源 dump 治理**：compat.rs 待拆分（S6）
6. **`OshiUtil::hardware()` 一次性 5 项采集**：每项调用 `refresh_*`，
   高频调用时请使用 `OshiUtil::system()` 复用 `System` 实例
