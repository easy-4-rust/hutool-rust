# hutool-ai 对象级对照表（验收清单）

基线：hutool-ai **5.8.43+**（hutool-ai 顶级包 + `core` 子包 + 7 个 model 子包），
Java 源约 **60+ 个类**（含 SPI、ServiceProvider、ServiceImpl、Config、Common 等）。
本文档回答"**每个 Java 对象落在哪个 Rust 文件**"，是结构拆分与补缺的验收清单。

## 命名与组织规则

1. 目录、文件名一律 snake_case；类型 PascalCase；方法 snake_case
2. **每个 .rs 文件只对应一个 Java 对象**（顶级 / 公共对象）
3. `mod.rs` 只做模块声明与 re-export，**禁止定义任何类型/逻辑**
4. Java 多层嵌套包（`cn.hutool.ai.model.deepseek`）只要求**最后一层目录**对齐
5. 每个文件头部必须有中文 doc 注释：说明对应 Java 类的全限定名、核心职责
6. **单源 dump 治理**：当前 `compat.rs` 706 行违规，已列入路线图 S6

## 四、不迁移（Java 生态特有）

| Java 类 | 原因 | Rust 替代 |
|---------|------|----------|
| `cn.hutool.ai.core.AIConfigRegistry` | Java 静态注册表 | `ModelName` 枚举穷举 |
| `cn.hutool.ai.model.*.Provider` SPI 实现类 | Java SPI | `ProviderService::request` match 分支 |
| `cn.hutool.ai.model.*.ServiceImpl` | 抽象委托类 | `ProviderService` 单类 |
| `cn.hutool.ai.model.*.Common` | 工具常量类 | `models.rs` 顶部常量 |
| `cn.hutool.ai.model.*.Config` 接口 | 厂商特定配置 | 统一 `BaseConfig` + `additional` |
| `META-INF/services/cn.hutool.ai.core.AIServiceProvider` | SPI 描述符 | 无需，编译期已知全部 7 厂商 |
