# hutool-ai 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：hutool **5.8.43+**（hutool-ai）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 hutool-ai 为蓝本实现功能语义对齐的 hutool-ai Rust crate：覆盖 Java 端
所有 AI 厂商（OpenAI / DeepSeek / Doubao / Gemini / Grok / Ollama / Hutool），
统一 AIConfig / AIService / Message / ModelName / Models 等核心抽象。
Java 侧的 `javax.script` 类 SPI 注册、Java 反射构造 Service Provider 等机制
不再适用 Rust，借助 **trait object + 工厂枚举** 完成等价映射。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java SPI ServiceLoader → 枚举分发；
   Java `Proxy` → `reqwest::Proxy` 字符串；Java 阻塞 HTTP → Rust 异步
   `hutool_http::HttpClient`
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 hutool-rust 的一文件一对象规范
3. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **API Key 一律通过 `secrecy::SecretString` 持有**，Debug 输出自动脱敏
6. **流式响应通过 `Arc<dyn Fn(String) + Send + Sync>` 回调传递**，不暴露内部 HTTP 状态机

## 四、与 Java hutool-ai 的主要差异

| 维度 | Java 实现 | Rust 实现 | 原因 |
|------|----------|----------|------|
| ServiceLoader 加载 | META-INF/services + ClassLoader | 枚举 `ModelName` | Rust 无 SPI |
| API Key 持有 | `String`（明文） | `SecretString`（自动脱敏） | 防止日志泄露 |
| HTTP 客户端 | `HttpClient` 可配 | `hutool_http::HttpClient` | 复用 crate |
| 流式响应 | `ServerSentEvent` 流 | `Arc<dyn Fn(String) + Send + Sync>` 回调 | 适配 Rust 异步 |
| 代理 | `java.net.Proxy` | `Url` 字符串 | reqwest 仅接受 URL |
| 厂商配置 | 各厂商 Config 类 | 统一 `BaseConfig` | Rust 端单一结构更易测试 |
| 超时 | int ms | `Duration` | 类型安全 |
| `Models.*` 嵌套枚举 | 内嵌 enum | 平铺 enum + 类型别名 | 避免命名冲突 |
| `AIServiceProvider` 加载 | SPI 反射 | `trait` + 工厂 | 无类路径概念 |

## 五、风险与限制

1. **生产环境密钥安全**：必须使用 `secrecy::SecretString`，禁止 `String` 直传
2. **限流与重试**：当前无重试；生产应通过 `hutool_http` 客户端层或外层中间件
3. **超时设置**：默认值 180s 连接 / 300s 读取；网络受限时应主动调小
4. **二进制响应上限**：默认 64 MiB，OASST/TTS 场景可适当调大
5. **SSE 解析**：256 KiB/event 上限，防止恶意服务端发送巨大事件
6. **Java SPI 兼容**：旧业务中通过 `META-INF/services/cn.hutool.ai.core.AIServiceProvider`
   自注册的 provider **不会自动加载**，需手动调用 `register_provider` 注册
