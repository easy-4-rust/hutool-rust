# hutool-bloom-filter 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（`cn.hutool.bloomFilter.*`）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Hutool 5.8.x 的 `hutool-bloomFilter` 模块（`cn.hutool.bloomfilter`，19 个非
`package-info` Java 类）为蓝本，实现功能语义完全对齐的 `hutool-bloom-filter` crate。
`hutool-bloom-filter` 提供两类能力：
1. **Hutool 兼容的位图（BitMap）+ 13 种哈希过滤器**（FuncFilter 及其 13 个具名实现）
2. **生产级泛型布隆过滤器**（基于成熟 `bloomfilter` crate 的二次封装）

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象；`long[]` 位图 →
   `Vec<u64>` / `Vec<u32>`；12 个具名哈希函数全部内联到 `hashes` 子模块
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 hutool-rust 一文件一对象规范
3. **公开类型必须有中文文档注释**：trait、struct、enum、函数、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **不实现 Java `BloomFilter` 接口类**：用 `StringBloomFilter` trait 替代
6. **`BloomFilterUtil` 作为静态方法聚合**：不对应单一 Java 类，标注为 🆕

### 与 hutool-bloom-filter 当前状态的差距

| 维度 | 当前 | 目标 |
|------|------|------|
| Java 类数 | 19 | 19 |
| Rust 文件数 | 5 | 19+ |
| BitMap | 1（`bitmap.rs`） | 1（聚合 IntMap/LongMap/MachineWord） |
| Hash 过滤器 | 1（`hashes.rs` 聚合 12 个具名实现） | 13（逐一拆分为独立文件） |
| 通用 `StringBloomFilter` | 1 trait | 1 trait |
| 通用 `BloomFilter` | 1（基于 bloomfilter crate） | 1（已有） |
| `BloomFilterUtil` | 1 聚合 | 1 聚合 |
| 测试 | 1（`tests.rs`） | 每文件 1 单测 |

## 五、风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| `hutool.rs` 单文件 dump 违规 | 违反 AGENTS.md 红线 | S6 拆分 |
| 12 个 Filter 拆分后导入繁琐 | 编译时间 | 使用 `mod.rs` 集中 re-export |
| 哈希函数行为兼容 | 与 Java Hutool 行为必须一致 | `hashes` 模块已对齐各常量 |
| `BitSetBloomFilter` 1-8 哈希数限制 | Java 同样限制 | `BloomFilterError::InvalidHashFunctionCount` 已对齐 |
| 跨平台位运算 | 32/64 位 | 区分 `IntMap` / `LongMap` |
