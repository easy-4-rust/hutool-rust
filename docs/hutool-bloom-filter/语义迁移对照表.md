# hutool-bloom-filter 功能语义迁移对照表

> 检查时间：2026-07-27
> 基线：Hutool 5.8.x `cn.hutool.bloomFilter.*`
> hutool-bloom-filter crate：5 个 `.rs` 文件

迁移原则：**功能语义对齐，实现方式 Rust 化**。
Java 的 `int[]` / `long[]` 位图映射为 `Vec<u32>` / `Vec<u64>`；
Java 的 `BloomFilter` 接口（仅支持 String）映射为 `StringBloomFilter` trait；
Java 的字符串哈希常量表（13 个）映射为 `hashes` 模块的 12 个具名 Filter。

状态图例：✅ 已迁移并有测试 / 🔀 语义已迁移但合并 / ⬜ 未迁移 / 🚫 不迁移 / 🆕 Rust 特有

## 七、Rust 特有（🆕 3 个）

### 7.1 `BloomFilter<T>` 泛型生产级布隆过滤器

| 字段 | 类型 | 语义 |
|------|------|------|
| `inner` | `Bloom<T>`（`bloomfilter` crate） | 底层引擎 |

| 方法 | 签名 | 语义 |
|------|------|------|
| `new` | `fn new(expected_items, fp_rate) -> Result<Self, BloomFilterError>` | 按容量和误判率构造 |
| `insert` | `fn insert(&mut self, &T) -> bool` | 插入并返回是否已存在 |
| `contains` | `fn contains(&self, &T) -> bool` | 检查存在性 |
| `bit_count` | `fn bit_count(&self) -> u64` | 已分配位数 |

> Java 端**无对应类**，Hutool 仅提供字符串过滤器。Rust 端基于 `bloomfilter` crate 提供
> 类型安全的泛型布隆过滤器，**可作为 `StringBloomFilter` 的替代**用于生产场景。

### 7.2 `BloomFilterError` 错误枚举

| 变体 | 触发条件 |
|------|----------|
| `EmptyCapacity` | `expected_items == 0` |
| `InvalidFalsePositiveRate` | 误判率不在 `(0, 1)` 区间 |
| `InvalidHashFunctionCount` | `BitSetBloomFilter` 哈希数不在 `[1, 8]` |
| `IndexOutOfBounds { index, capacity }` | 位图索引越界 |
| `CapacityOverflow` | 容量溢出平台地址空间 |
| `Io(io::Error)` | 文件初始化失败 |
| `InvalidEncoding(&'static str)` | 输入字节不是合法的字符编码 |

> Java 端用 `IllegalArgumentException` 表达，Rust 端用 `thiserror` 派生更精细的诊断。

### 7.3 `MachineWord` 枚举

| 变体 | Java 等价 |
|------|----------|
| `Bits32` | `int[]` 位图（最大 `2^31 - 1` 位） |
| `Bits64` | `long[]` 位图（最大 `2^63 - 1` 位） |
