# hutool-log 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：hutool **5.8.43+**（hutool-log）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护

## 一、总目标

以 hutool-log 为蓝本实现功能语义对齐的 hutool-log Rust crate：覆盖 Java
端 Hutool 日志抽象（`Log` / `LogFactory` / `StaticLog` / `AbstractLog`）以及
10+ 个 dialect 实现（slf4j / log4j / log4j2 / jdk / console / commons-logging /
jboss / tinylog / logtube 等）。

底层后端使用 **Rust `tracing` 生态**（`tracing` + `tracing_subscriber`），不
引入 `slog` / `log4rs` 等竞争库，保持与 hutool-rust 其它模块的一致性。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 SPI 加载 dialect →
   编译期类型别名；Java 静态字段缓存 → `OnceLock<RwLock<LogFactory>>`
2. **每个 .rs 文件只对应一个 Java 对象**：兼容层已正确拆分
3. **公开 API 必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **`tracing` 是默认实现层**：所有 dialect（slf4j/log4j/jboss 等）都是
   `TracingLog` 的类型别名
5. **`RUST_LOG` 环境变量优先**：与 Java 的 `logging.properties` 对齐
6. **结构化日志**：通过 `LogRecord` 后端无关事件传输
7. **`Redacted<T>` 防泄漏**：密钥、Token 等不通过 `Debug/Display` 输出

## 四、与 Java hutool-log 的主要差异

| 维度 | Java 实现 | Rust 实现 | 原因 |
|------|----------|----------|------|
| 底层后端 | slf4j / log4j / log4j2 / jboss / tinylog 等多种 | `tracing` 单一生态 | 统一 |
| dialect 加载 | `ServiceLoader` 反射 | 编译期 `pub type` 别名 | 无 SPI |
| 默认后端 | 探测 classpath | `TracingSink` 强制 | 简化 |
| 模板替换 | `String.format` `{}` | 自实现 `format_message` | 兼容 |
| `log4j` 支持 | 完整 | 通过 `tracing-log` 桥接 | 复用 |
| 异步日志 | AsyncAppender | `tracing` 内置异步 | 内建 |
| 结构化字段 | MDC / NDC | `tracing::Span` | 内建 |
| 异常堆栈 | `Throwable` 序列化 | `Option<String>` 简化 | 防泄漏 |
| 全局状态 | `StaticLogFactory` 静态字段 | `OnceLock<RwLock<LogFactory>>` | 类型安全 |
| Caller 信息 | `CallerUtil.getCallerCaller()` | `LogRecord::fqcn` | 静态门面保留 |
| 配置文件 | `logging.properties` | `RUST_LOG` 环境变量 | 标准 |
| 时间格式 | `PatternLayout` | `tracing_subscriber` 默认 | 内建 |

## 五、风险与限制

1. **dialect 全部走 tracing**：业务侧需要 slf4j / log4j 兼容时通过
   `tracing-log` crate 桥接
2. **`RUST_LOG` 解析失败回退默认**：避免 panic
3. **`init()` 只能调用一次**：tracing 限制；多次调用返回错误
4. **`Redacted<T>` 手动包装**：避免误用 `String` 持有密钥
5. **模块级中文说明补全**：当前 11 个 compat 文件需统一模板
6. **测试覆盖**：当前覆盖 80%，边界 case 仍需补充
