# hutool-jwt 功能语义迁移对照表

> 检查时间：2026-07-27
> 基线：Hutool 5.8.x `cn.hutool.jwt.*`
> hutool-jwt crate：2 个 `.rs` 文件（`lib.rs` + `compat.rs`）

迁移原则：**功能语义对齐，实现方式 Rust 化**。
Java `io.jsonwebtoken:jjwt` / `com.nimbusds:nimbus-jose-jwt` / `org.bouncycastle:bcprov`
分别映射为：`jsonwebtoken` / `jsonwebtoken` / `rsa` + `p256`。
Java 反射调 `Key` 字段映射为 RustCrypto 显式 `DecodingKey` / `EncodingKey`。

状态图例：✅ 已迁移并有测试 / 🔀 语义已迁移但合并 / ⬜ 未迁移 / 🚫 不迁移 / 🆕 Rust 特有

---

## 三、Rust 特有（🆕 3 个，无 Java 对偶）

### 3.1 `JwtValidationPolicy` struct

| 字段 | 类型 | 语义 |
|------|------|------|
| `issuer` | `String` | 必需 `iss` |
| `audience` | `String` | 必需 `aud` |
| `leeway_seconds` | `u64` | 时钟偏移容差 |
| `require_expiration` | `bool` | 是否校验 `exp` |

> Java `JWTValidator` 字段隐式且必填，Rust 用显式 policy + builder。

### 3.2 `JwtHs256` struct

| 字段 | 类型 | 语义 |
|------|------|------|
| `encoding_key` | `jsonwebtoken::EncodingKey` | HS256 编码密钥 |
| `decoding_key` | `jsonwebtoken::DecodingKey` | HS256 解码密钥 |
| `validation` | `jsonwebtoken::Validation` | 验证策略 |

| 方法 | 签名 | 语义 |
|------|------|------|
| `new` | `(secret, policy) -> Self` | 构造 codec |
| `encode` | `encode<T: Serialize>(claims) -> Result<String, Error>` | 编码 |
| `decode` | `decode<T: DeserializeOwned>(token) -> Result<TokenData<T>, Error>` | 解码 |

> Java `JWT.create().setSigner(HS256).sign()` 流程在 Rust 端用 `JwtHs256` 一步封装。

### 3.3 单元测试（`lib.rs::tests`）

| 测试 | 语义 |
|------|------|
| `encodes_and_validates_claims` | 完整签发 + 验签 + 拒绝错误密钥 + 拒绝错误 audience |
| `rejects_malformed_standard_claim_types` | 拒绝 `nbf` 类型错误 |
