# hutool-crypto → hutool-crypto 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（`hutool-crypto`）
> 仓库：easy-4-rust/hutool-rust @ main ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Hutool 5.8.x 的 `hutool-crypto` 模块为蓝本，实现功能语义完全对齐的
`hutool-crypto` crate。基线 Java 包 `cn.hutool.crypto` 共 **64 个非 `package-info` 类**，
覆盖对称加密、非对称加密、消息摘要、HMAC、国密 SM2/SM3/SM4、PEM/X.509、签名验签、
密钥派生、OTP 等完整密码学生态。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：BouncyCastle → RustCrypto；
   `java.security.Provider` → trait 对象；`javax.crypto.Cipher` → 各算法独立封装
2. **每个 `.rs` 文件只对应一个 Java 对象**：对齐 `hutool-rust` 的一文件一对象规范
3. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **国密算法独立**：sm2/sm3/sm4 各自模块，使用 `libsm` crate
6. **不依赖 BouncyCastle**：全部用纯 Rust 实现，跨平台无 JRE 依赖

### 与 hutool-crypto 当前状态的差距

| 维度 | 当前 | 目标 |
|------|------|------|
| Java 非 `package-info` 类 | 64 | — |
| Rust `.rs` 文件 | 50 | 64+ 顶级 + 子模块文件 |
| 顶级 `cn.hutool.crypto` 类 | 14 | 14 |
| `asymmetric/` 子包 | 11 | 11 |
| `symmetric/` 子包 | 14 | 14 |
| `digest/` 子包（含 `mac/` `otp/`） | 19 | 19 |
| 单源 `compat.rs` dump | 0 | 0 ✅ |
| 空实现占位 | 0 | 0 ✅ |

> 当前 hutool-crypto 已有 50 个 Rust 文件，超过 Java 端 14 个；剩余工作量主要是
> **算法覆盖完整性**（国密、DES/3DES、ChaCha20、ZUC）和 **配置语义一致性**。

## 七、风险评估

| 风险 | 影响 | 对策 |
|------|------|------|
| 国密合规性 | SM2/SM3/SM4 互操作性 | 严格按 GM/T 0003/0004 标准实现 |
| RSA 填充差异 | PKCS#1 vs OAEP | `Mode` / `Padding` 枚举透传 |
| 随机数源 | 安全 | 强制使用 `OsRng` |
| 内存安全 | 密钥泄漏 | `secrecy::SecretString` 包装 |
| 时间常数攻击 | 侧信道 | `subtle` crate + 常数时间比较 |
| BC 兼容性 | BouncyCastle Provider 缺失 | 全部用 RustCrypto 替代 |
| 跨语言互通 | PEM/DER 编码 | `der` / `pem` crate |
