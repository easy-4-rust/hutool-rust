## 一、总目标

以 Hutool 5.8.x `hutool-captcha` 模块（`cn.hutool.captcha.*` 共 **11 个 Java 类**）为蓝本，
实现功能语义完全对齐的 `hutool-captcha` crate。**目标 11 个 Java 类 → 11 个独立 Rust 文件**
（禁止合并到 `compat.rs`）。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：
   - `java.awt.image.BufferedImage` → `image::RgbaImage`（`image` crate）
   - `java.awt.Graphics2D` → 自实现的 `PngRenderer`（用像素直接绘制）
   - `javax.imageio.ImageIO.write` → `image::ImageEncoder`
   - `AnimatedGifEncoder` → `gif` crate + 自定义帧延迟
   - `java.util.Random` → `rand::rngs::ThreadRng`
2. **每个 .rs 文件只对应一个 Java 对象**：禁止把多个 Java 类合并到 `compat.rs`。
3. **保留所有已有迁移内容**：hutool-captcha 当前 7 个 Rust 文件（含 compat.rs），
   顺原思路继续，不得删减。
4. **公开类型必须有中文文档注释**：结构体、trait、方法、字段。
5. **依赖 `hutool-core`**：复用 `img/`、`lang/`、`util/`、`random_util/` 等基础设施。
6. **测试覆盖**：每种验证码（Line / Circle / Shear / Gif）至少 1 个行为测试。

### S2 — lib.rs 瘦身

当前 `lib.rs`：

```rust
#[cfg(feature = "raster")]
mod compat;
#[cfg(feature = "raster")]
pub use compat::{
    AbstractCaptcha, AbstractGenerator, CaptchaColor, CaptchaFont, CaptchaStroke, CaptchaUtil,
    CircleCaptcha, GifCaptcha, ICaptcha, LineCaptcha, MathGenerator, RandomGenerator, ShearCaptcha,
};
```

拆分后改为：

```rust
#[cfg(feature = "raster")]
mod captcha_util;
#[cfg(feature = "raster")]
mod icaptcha;
#[cfg(feature = "raster")]
mod abstract_captcha;
#[cfg(feature = "raster")]
mod line_captcha;
#[cfg(feature = "raster")]
mod circle_captcha;
#[cfg(feature = "raster")]
mod shear_captcha;
#[cfg(feature = "raster")]
mod gif_captcha;
#[cfg(feature = "raster")]

```

`lib.rs` 行数应 ≤ 100。

### S3 — 中文注释收尾

每个 `.rs` 文件头必须含：
- `//! 对齐: cn.hutool.captcha.<ClassName>`
- `//! 来源: hutool-captcha/src/main/java/cn/hutool/captcha/<ClassName>.java`
- `//! 中文说明: ...`

方法前必须有中文文档注释，复制自 Java Javadoc。

## 四、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| `java.awt.Graphics2D` 移植复杂 | 高 | 用像素级算法直接绘制（避开 AWT 抽象） |
| AnimatedGifEncoder 字节码移植 | 高 | 用 `gif` crate + 自定义 frame delay |
| ShearCaptcha 字体变形算法 | 中 | 用 `imageproc` crate 仿射变换 |
| compat.rs 拆分破坏现有 API | 中 | 保留 `pub use` 路径不变 |
