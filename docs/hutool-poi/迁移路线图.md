> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（`hutool-poi`）

## ⚠️ 重要声明

**对象/方法/参数已对齐，方法体留空实现，等待 `easyexcel-rust` /
`easydoc-rust` / `easyofd-rust` / `easypdf-rust` 完成后回填。**

> 本 crate 当前所有公开方法均使用 `unimplemented!()` 占位（**67 / 79 文件**），

## 一、总目标

以 Hutool 5.8.x 的 `hutool-poi`（`cn.hutool.poi`）为蓝本，构建
`hutool-poi` crate，作为 Java POI / OOXML 库的 Rust 等价门面。

### 1.1 设计原则

1. **门面优先**：hutool-poi 是 facade crate，**不直接实现 Excel/OFD/Word 引擎**，
   实际功能由 `easyexcel-rust` / `easydoc-rust` / `easyofd-rust` / `easypdf-rust`
   提供
2. **结构对齐**：Java 的 `cn.hutool.poi.excel.ExcelUtil` → Rust 的
   `hutool_poi::excel::ExcelUtil`，公开 API 一一对应
3. **方法签名一致**：方法名、参数列表、返回类型与 Java 完全对齐（忽略 Java 的
   重载差异，Rust 通过 trait + 默认值实现）
4. **方法体留空**：所有方法体 `unimplemented!()`，仅作为"接口契约"占位
5. **依赖注入**：通过 trait 抽象引擎接口，便于切换底层实现

### 1.2 关键文件统计

| 维度 | 数量 |
|------|------|
| Java 类总数 | **78**（含子包） |
| Rust 文件总数 | **79**（含子包） |
| unimplemented 文件 | **67** |
| 已实现文件 | 12（基础结构） |
| 子包镜像完成度 | **100%**（路径完全对齐） |
| 方法体实现完成度 | **< 5%**（等待底层 crate） |

## 七、命名约定

- **结构体 / 枚举 / Trait**：`PascalCase`（与 Java 一致）
- **方法 / 函数**：`snake_case`（与 Java `camelCase` 不同）
- **模块 / 文件名**：`snake_case`（与 Java `lowercase` 不同）
- **常量**：`SCREAMING_SNAKE_CASE`

## 八、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 底层 crate 长期未完成 | 🔴 高 | 保留 `unimplemented!()` 状态，方法签名可冻结 |
| Java 反射 API 在 Rust 中无对等 | 🟡 中 | 用 trait + `Any` 模拟 |
| 大量公开方法导致 trait 冲突 | 🟡 中 | 拆为多个 trait（`ExcelReader` / `ExcelWriter` / `ExcelEditor`） |
| Excel 性能（10w+ 行） | 🟡 中 | 委托给底层 `easyexcel-rust` 的流式 API |
| OFD 格式复杂度 | 🟢 低 | 等待 `easyofd-rust` 团队 |
| Word doc/docx 兼容性 | 🟡 中 | doc 旧格式由 `easydoc-rust` 解决 |
