## 统一阶段

```mermaid
flowchart LR
    S0["S0 固定基线与清单"] --> S1["S1 一对象一文件/签名"]
    S1 --> S2["S2 纯逻辑/错误/格式"]
    S2 --> S3["S3 SPI/I-O/并发"]
    S3 --> S4["S4 Java golden/live 差分"]
    S4 --> S5["S5 真实宿主/负载/安全"]
    S5 --> S6["S6 灰度与回滚"]
```

1. S0 文档基线与 CodeGraph 索引已生成；内部类、继承、泛型与动态分派仍需语言级复核。
2. S1 必须清零 layout audit 的 217 errors/23 warnings，并保持 API 行为。
3. S2-S3 逐垂直切片迁移，不按文件数宣布完成。
4. S4 绑定当前双 SHA 生成 golden/live artifact；单端镜像测试不计差分。
5. S5-S6 完成真实依赖、并发、fuzz、负载、安全、灰度和回滚。

## Rust 扩展 crate

`hutool-annotation`、`hutool-macro`、`hutool-observability`、`hutool-vernal`、
`hutool-test-support`、`hutool-compat-hutool` 属于 Rust adapter/宏/治理扩展，
不进入 Java 功能对象分母；其承担的 Java 对象在来源模块对象表中以跨 crate 候选记录。
