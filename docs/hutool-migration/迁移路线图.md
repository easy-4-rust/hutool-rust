## 一、总目标

以 Hutool 5.8.x 的 21 个 Java 子模块（`hutool-ai`、`hutool-aop`、`hutool-bloomFilter`、
`hutool-cache`、`hutool-captcha`、`hutool-core`、`hutool-cron`、`hutool-crypto`、
`hutool-db`、`hutool-dfa`、`hutool-extra`、`hutool-http`、`hutool-json`、`hutool-jwt`、
`hutool-log`、`hutool-poi`、`hutool-script`、`hutool-setting`、`hutool-socket`、
`hutool-system`）为蓝本，实现功能语义对齐的 Rust 1:1 镜像，目标 **1332+ 个 Java 类 →
等价 Rust 文件**。hutool-rust 在仓库中扩展为 26 个 crate（含 `hutool-macro`、
`hutool-observability`、`hutool-vernal`、`hutool-test-support`、`hutool-compat-hutool`
等扩展）。

### 设计原则（来自 `AGENTS.md`）

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象 / serde；Spring → axum；
   Quarkus → actix；Jackson → serde；JCA → RustCrypto；ClassLoader → 模块路径。
2. **每个 .rs 文件只对应一个 Java 对象**（禁止 1:N 或 N:1，禁止把多个 Java 类合并到一个
   `compat.rs` 后由其他文件 `pub use`）。已经实现的内容**不得删减**，要顺着原思路继续迁移。
3. **保留 Rust 默认 snake_case 目录与文件**（如 `context/`、`dao/`），文件内部类型用
   `PascalCase`、方法 `snake_case`、参数命名与 Java 一致。
4. **多层嵌套子包只对齐最后一层**：例如 `cn.hutool.core.io.checksum.crc16.CRC16Ansi`
   → `hutool-core/src/io/checksum/crc16/crc16_ansi.rs`（`crc16_ansi` 是最终段，
   `io/checksum` 作为路径前缀保留以维持子包嵌套语义）。
5. **Java 注释必须同步复制**到 Rust 文件（结构体注释、方法注释、代码段落注释），使用中文
   并在文件头标注原 Java 文件路径。
6. **hutool-poi 当前仅做对象/方法/参数对齐**，内部留空实现，等待后续
   `easyexcel-rust`/`easydoc-rust`/`easyofd-rust`/`easypdf-rust` 完成后回填。
7. **`hutool-core/src/annotation` 已迁移为独立 crate `hutool-macro`**
   （86 个 Rust 文件 vs Java 46 个文件，含 `hierarchical`/`mirror`/`scanner`/`element`
   等子目录），与 `sa-token-rust/sa-token-macro` 模式一致。

### 禁止事项（红线）

- ❌ **不得** 在 `lib.rs`、`compat.rs` 中塞入大量对象。`lib.rs` 仅做 `mod` 声明 +
  `pub use` re-export；`compat.rs` 单文件不得超过 200 行。
- ❌ **不得** 用单一 `compat.rs` 集中定义所有对象再让其他文件 `pub use` 引用。
- ❌ **不得** 出现空方法（`fn foo() {}`）或仅返回 `unimplemented!()`/`todo!()` 的占位实现。
- ❌ **不得** 一个 `.rs` 文件对应多个 Java 对象。每个 `.rs` 必须与一个 Java 类
  严格一一对应。
