## 四、业务逻辑一致性检查

### ✅ 完全一致的逻辑

- HTTP 方法枚举（GET/POST/PUT/DELETE/HEAD/OPTIONS/PATCH）
- 链式 API（header / cookie / timeout / form / body）
- Multipart 文件上传（boundary 自动生成）
- Form URL 编码（application/x-www-form-urlencoded）
- Cookie 持久化（线程局部 + 全局）
- User-Agent 解析（Browser/Engine/OS/Platform）
- HTTP 状态码分类（1xx/2xx/3xx/4xx/5xx）
- HTTP 协议版本（HTTP/1.0、HTTP/1.1）
- SOAP 1.1 客户端（基于 `SoapClient` + `SoapProtocol`）
- Jakarta SOAP（与 javax/jakarta 命名空间切换）
- 异常映射（`HttpException` 聚合网络/超时/SSL 错误）

### ⚠️ 部分一致的逻辑

- 自定义 TLS 协议：Java 通过 `SSLSocketFactory`，Rust 通过 `TlsProtocol` 枚举
- HTML 过滤：Java 直接 `org.jsoup`，Rust 通过 `feature = "html"` 弱依赖
- 拦截器：Java 通过 ThreadLocal，Rust 通过 `GlobalInterceptor` 单例
- 进度回调：Java 通过 `Progress` listener，Rust 通过 `StreamProgress` trait

### ❌ 未实现的逻辑

- WebSocket 客户端（Java Hutool 不直接提供）
- HTTP/2 服务端推送
- HTTP/3（QUIC）

## 五、命名差异说明

| Java 名 | Rust 文件名 | 差异原因 |
|---|---|---|
| `OS` | `operating_system.rs` | 避免与 `std::os` 冲突 |
| `Method` | `request.rs`（内嵌） | 复用 `reqwest::Method` |
| `Status` | `metadata.rs`（内嵌） | 聚合 `Status/HttpStatus/Header/ContentType/GlobalHeaders` |
| `Header` | `metadata.rs`（内嵌） | 同上 |
| `ContentType` | `metadata.rs`（内嵌） | 同上 |
| `GlobalHeaders` | `metadata.rs`（内嵌） | 同上 |
| `HttpStatus` | `metadata.rs`（内嵌） | 同上 |
| `SimpleServer` | `server/simple_server.rs` | 完全一致 |
| `CustomProtocolsSSLFactory` | `custom_protocols_ssl_factory.rs` | 缩写大写：`SSL` → `Ssl` |
| `TrustAnyHostnameVerifier` | `trust_any_hostname_verifier.rs` | 缩写小写 |
