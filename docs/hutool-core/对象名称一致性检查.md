# hutool-core → hutool-rust 对象名称一致性检查

本文档针对 hutool-core 当前实际文件树，逐个 Java 类核对对应 Rust 文件，
重点检查：
1. **重名 .rs 文件**（14 组必须解决）
2. **类名到文件名的 1:1 映射**（snake_case 规则）
3. **子包内文件命名一致性**（Java `cn.hutool.core.util.XxxUtil` → Rust `util/xxx_util.rs`）
4. **crate 根目录 vs 子包目录的归属**

## 一、重名 .rs 文件清单（核心问题）

`crates/hutool-core/src/` 根目录与 `crates/hutool-core/src/util/` 下存在 **14 组
同名 .rs 文件**。每个文件名都重复出现两次，违反"一文件一对象"规范。

### 1.2 解决方案

**推荐方案**：统一到 `util/` 子包，根目录仅保留 facade `pub use`。

```rust
// src/str_util.rs（重写为 facade）
//! 对齐 cn.hutool.core.util.StrUtil
pub use crate::util::str_util::*;
```

```rust
// src/util/str_util.rs（保留完整实现）
//! 对齐 cn.hutool.core.util.StrUtil
//! 提供完整的字符串工具方法
pub struct StrUtil;
impl StrUtil { /* ... */ }
```

**关键约束**：
- `lib.rs` 中**先**声明 `pub mod str_util;`（子包），**再**使用 `mod str_util;` 会被冲突
- 根目录同名文件**不能**再次 `pub mod` 同一个名字
- 根目录 facade **不能**使用 `pub mod str_util;`，必须用 `mod str_util;` + 显式 `pub use crate::util::str_util::*;`

## 四、命名风格一致性检查

### 4.1 命名规则

- **结构体 / 枚举 / Trait**：`PascalCase`（与 Java 一致）
- **方法 / 函数**：`snake_case`（与 Java `camelCase` 不同）
- **模块 / 文件名**：`snake_case`（与 Java `lowercase` 不同）
- **常量**：`SCREAMING_SNAKE_CASE`
