# hutool-core → hutool-rust 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（`hutool-core`）
> 仓库：easy-4-rust/hutool-rust @ main ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Hutool 5.8.x 的 `hutool-core`（`cn.hutool.core`）模块为蓝本，实现功能语义完全
对齐的 `hutool-core` crate。目标覆盖 Java 端 `cn.hutool.core.*` 全部 30+ 子包，
把 Java 反射、字节码操作、动态代理等 JVM 特性分别映射为：Rust trait 对象、
编译期宏、过程宏。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象 + `Any`；ClassLoader
   → 模块路径；动态代理 → trait object 装箱；JIT → 不需要
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 liteflow-rust 的一文件一对象规范
3. **公开类型必须有中文 doc 注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **子包最后一层目录必须与 Java 包名 1:1 对齐**（`util/`、`text/`、`map/`、`net/`）
6. **顶层 facade 由 `crate root` 提供**：Java 端 `cn.hutool.core.XxxUtil` 在 Rust
   端映射为 `pub use crate::xxx::XxxUtil`

### 与 hutool-core 当前状态的差距

| 维度 | 当前 | 目标 | 备注 |
|------|------|------|------|
| Java 类总数 | 700+ | — | 含各子包 |

| 已通过编译 | 部分 | 全部 | 当前有重名文件 |
| 子包覆盖率 | 30+/30+ | 30+/30+ | 完整 |

## 三、关键问题：重名 .rs 文件清单（必须解决）

`crates/hutool-core/src/` 根目录与 `crates/hutool-core/src/util/` 下存在 **14 组
同名 .rs 文件**，违反一文件一对象规范、且会让 `cargo doc` 在两处都生成同名 HTML。
必须二选一：**统一到 `util/` 子包**（推荐，符合 Java 端 `cn.hutool.core.util.*`
1:1 对齐），或**统一到根目录**（更接近 Rust 习惯）。

## 四、hutool-annotation 独立 crate 说明

**`hutool-annotation` 不在 workspace `crates/` 目录下**，而是**顶层独立 crate**：

```
hutool-rust/
├── Cargo.toml                       # workspace root（resolver = "3", members = ["crates/*"]）
├── crates/
│   ├── hutool-core/                 # 本文档主体
│   ├── hutool-poi/
│   └── ...（其余 20+ 子 crate）
└── hutool-annotation/               # ⚠️ 独立 crate，不被 workspace 包含
    ├── Cargo.toml                   # 自有 package，无 [workspace]
    └── src/
        ├── mod.rs
        ├── alias.rs                 # 对齐 cn.hutool.core.annotation.Alias
        ├── alias_for.rs
        ├── annotation_util.rs       # 对齐 AnnotationUtil
        ├── link.rs
        ├── mirror.rs
        ├── mirror_for.rs
        ├── prop_ignore.rs
        ├── relation_type.rs
        ├── scanner/                 # 9 个扫描器
        └── ...（约 40 个 .rs 文件）
```

**注意**：`hutool-core` 当前 `lib.rs` 第 64-65 行有明确注释：

```rust
// annotation 模块已迁移到独立 crate hutool-macro
// hutool-core 不再内嵌 annotation；facade crate (hutool) 负责 re-export
```

但实际目录结构是 `hutool-annotation/`（不是 `hutool-macro/`）。**本路线图以
实际目录为准**：在 `hutool-rust/hutool-annotation/` 下找到 40+ 个 .rs 文件，
与 Java `cn.hutool.core.annotation.*` 1:1 镜像。

## 六、与 vernal-framework 的关系

`hutool-core` 是 `easy-4-rust` 整个 Java → Rust 迁移计划的基础设施层。
`vernal-framework` 的 `vernal-expression`、`vernal-messaging` 等子模块都可能
`use hutool_core::*`。本路线图优先保证 `hutool-core` 的 API 稳定性。
