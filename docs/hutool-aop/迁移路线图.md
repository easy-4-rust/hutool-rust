# hutool-aop 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Hutool **5.8.x**（cn.hutool.aop）
> 仓库：easy-4-rust/hutool-rust @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Hutool 5.8.x `hutool-aop` 模块（`cn.hutool.aop.*` 共 **11 个 Java 类**）为蓝本，
实现功能语义完全对齐的 `hutool-aop` crate，目标 **15+ 个 Rust 文件**，覆盖代理、
拦截器、切面、Spring 集成等全部子能力。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：JDK `Proxy` / CGLIB → trait 对象 + 显式包装；
   拦截器链 → `Interceptor` trait + `InterceptorChain`；`@Aspect` → procedural macro
   （参考 `sa-token-rust/sa-token-macro` 模式）；Spring 集成 → 移除 Spring 容器依赖
   改为 `ProxyBackend` 枚举 + trait 抽象。
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 liteflow-rust / hutool-core 的规范，
   `aspects/aspect.rs` 对应 `Aspect`，`aspects/simple_aspect.rs` 对应 `SimpleAspect`，
   `aspects/time_interval_aspect.rs` 对应 `TimeIntervalAspect`。
3. **所有公开类型必须有中文文档注释**：结构体、trait、方法、字段。
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case。
5. **依赖 `hutool-core`**：复用 `func/`、`lang/`、`exception/` 等基础设施。
6. **测试不依赖 JVM**：使用 Rust 原生 `#[test]` 与 `tokio::test` 验证拦截顺序、
   异常抑制、计时统计等行为。

### 与当前 hutool-aop 状态的差距

| 维度 | 当前 | 目标 |
|------|------|------|
| Java 类数 | 11 | 11（基线） |
| Rust 文件数 | 20 | ≥ 15（一文件一对象） |
| Proxy 后端 | 2（JDK/CGLIB） | 1 + 枚举抽象（ProxyBackend） |
| 切面宏 | 0 | 1（`#[hutool_aop::aspect]`） |
| 测试覆盖 | 已有 `aop_parity.rs` | 全对象 1+ 测试 |

### S6 — `#[aspect]` procedural macro（⬜ 待办）

## 四、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| JDK Proxy 在 Rust 中无直接对偶 | 中 | 引入 `ProxyBackend` 枚举，运行时选择 |
| CGLIB 字节码生成在 Rust 中不可能 | 中 | 使用 trait 对象 + 显式 `dyn` 调度 |
| Spring 容器在 Rust 生态不存在 | 低 | `SpringCglibProxyFactory` 留作兼容性占位，标记为 🔶 |
| `#[aspect]` 宏需要 syn/quote | 低 | 复用 sa-token-macro 已建立的依赖 |
